# YEHAVHA Nexus 글·연구 아카이브 편집 원칙

## 목적

이 영역은 전자책 판매 페이지와 분리하여 완성된 연구 글을 웹에서 직접 읽을 수 있도록 축적하는 공개 아카이브다. 성경·신학, AI·Suno, 히브리어·언어를 포함하여 향후 어떤 주제의 글도 같은 형식으로 추가할 수 있다.

웹에서 읽은 글을 이후 전자책 본문으로 옮기기 쉽도록 화면 장식보다 제목 체계와 문단 구조를 우선한다.

## 글의 기본 순서

각 글은 다음 순서로 정리한다.

1. 제목
2. 부제목이 필요한 경우에만 부제목
3. 지은이
4. 짧은 목차
5. 장과 절로 구분한 본문
6. 필요한 경우 성경 구절, 인용, 주석
7. 관련 글
8. 저작권 표기와 맨 위로 이동

목차는 본문의 장과 절 제목에서 자동으로 생성한다. 목차는 본문보다 작게 표시하며 독서를 방해할 정도로 크게 만들지 않는다.

## 장과 절의 구조

본문의 큰 단위는 장으로 구분한다. 화면의 h2가 장에 해당한다.

장 안의 세부 논점은 절 또는 항으로 구분한다. 화면의 h3가 절 또는 항에 해당한다.

장과 절 사이에 장식 목적의 가로 구분선을 사용하지 않는다. 제목의 크기와 여백만으로 구조를 구분한다.

## 문단 규칙

한 문장을 하나의 문단으로 반복하여 배치하지 않는다.

하나의 논점을 이루는 문장들은 원칙적으로 2문장부터 4문장 정도의 한 문단으로 묶는다. 다만 논리 전환, 성경 구절 제시, 핵심 결론처럼 독립성이 필요한 경우에는 짧은 문단을 허용한다.

본문의 행간과 문단 간격은 지나치게 넓히지 않는다. 스마트폰에서도 연속해서 읽을 수 있을 정도의 밀도를 유지한다.

문단은 길기만 하게 만들지 않는다. 한 문단 안에서 하나의 중심 논점을 유지하고 다음 논점으로 넘어갈 때 새 문단을 시작한다.

## 문장부호와 작성 흔적

작성 과정에서 사용된 별표, 임시 마크다운 기호, 메모용 기호, 불필요한 점표시와 장식 문자는 공개 본문에서 제거한다.

콜론과 세미콜론은 꼭 필요한 경우가 아니면 사용하지 않는다. 문장을 자연스럽게 나누거나 조사와 연결어를 사용하여 일반 문장으로 정리하는 것을 우선한다.

문장 끝의 마침표는 정상적으로 사용하되 기호가 문장의 구조를 대신하지 않도록 한다.

목록은 정보의 병렬성이 분명할 때만 사용한다. 설명이 필요한 내용은 가능한 한 일반 문단으로 작성한다.

## 성경·신학 글 편집 원칙

성경 저자를 현대적 의미의 논증가로 규정하거나 저자가 독자적으로 철학적 논증을 설계했다는 식으로 서술하지 않는다.

성경은 성령의 영감 아래 사람을 통해 기록된 말씀이라는 신앙적 전제를 존중한다. 따라서 본문의 지혜와 지식과 통찰이 인간 저자의 독자적 지적 설계만으로 발생한 것처럼 표현하지 않는다.

현재의 연구와 분석이 성경 본문에서 논리적 구조, 상호 연결, 반복되는 패턴 또는 깊은 통찰을 발견하는 경우에는 다음 세 층위를 구분한다.

1. 성경 본문 자체가 증언하는 내용
2. 성령의 영감에 관한 신앙적 이해
3. 현재 연구자가 본문을 비교하고 분석하여 제시하는 해석과 논증

현대 연구자가 논증하는 것과 성경 본문이 증언하는 것을 혼동하지 않는다.

성경의 지혜와 지식이 인간의 일반적인 사유를 능가하는 구조로 드러난다고 평가할 수 있으나 이를 성경 기록자가 현대적 분석 방법을 의식적으로 사용했다는 식으로 환원하지 않는다.

## 성경 구절과 인용

성경 구절은 일반 본문과 시각적으로 구분하고 장절을 함께 표시한다.

성경 구절을 제시한 뒤에는 필요한 경우 해당 구절이 현재 논점과 어떤 관계를 갖는지 일반 문단으로 설명한다.

인용문과 주석은 본문의 흐름을 보조하는 수준으로 사용하고 본문 전체가 인용 박스와 목록으로 분절되지 않도록 한다.

## 전자책 재사용 원칙

웹 전용 장식과 기능은 본문 내용과 분리한다. 제목, 지은이, 목차, 장과 절, 본문을 그대로 복사하면 전자책 원고의 기본 골격이 되도록 한다.

이미지는 이 단계에서 필수 요소로 두지 않는다. 전자책 제작 시 필요한 위치에 별도로 추가한다.

인공지능 활용 여부와 제작 과정에 관한 설명은 본문에 자동으로 삽입하지 않는다.

## 데이터 운영

글 목록과 메타데이터는 `articles.json`에서 관리한다.

실제 본문은 `content/<article-id>.json`에 한 글씩 분리하여 저장한다.

새 글을 추가할 때 기존 화면 코드를 복제하지 않고 데이터와 본문 파일만 추가한다.

본문 입력 시 heading level 2는 장, heading level 3은 절 또는 항으로 사용한다. 별도의 divider 블록은 사용하지 않는다.
